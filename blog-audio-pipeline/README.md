# גרסת שמע בעברית לפוסטים בבלוג

הפקת קובץ MP3 קבוע לכל פוסט שפורסם ב-`noamdoronmath.co.il`, עם נגן והורדה בעמוד הפוסט.
ההקראה מופקת ב-Gemini TTS בקול `Charon`, מקודדת ל-MP3 מונו 24kHz‏ 128kbps, נשמרת באחסון קבוע
ונרשמת באוסף נתונים באתר.

**מפתח ה-API לא נמצא בקוד, לא ב-Git, לא בדפדפן ולא בלוגים.** ראו "הזנת המפתח" למטה.

---

## 1. מה יש כאן

| נתיב | תפקיד |
|---|---|
| `bin/verify-access.mjs` | בדיקת כל ההרשאות והחיבורים. לא מפיק שמע ולא עולה כסף. |
| `bin/map.mjs` | מיפוי כל הפוסטים + אומדן עלות. **בלי שום קריאה ליצירת שמע.** |
| `bin/generate.mjs` | הפקת ההקראות. הסקריפט היחיד שמוציא כסף. |
| `bin/verify-audio.mjs` | הוכחה שההקראה מלאה: תמלול חוזר והשוואה לטקסט המקור. |
| `bin/status.mjs` | מה הושלם, מה נכשל, כמה הוצאנו. |
| `bin/selftest.mjs` | בדיקה עצמית לא-מקוונת של כל המנגנון. בלי קריאות ל-Gemini ובלי עלות. |
| `src/text.mjs` | הפיכת פוסט לטקסט הקראה: ניקוי, מספרים, קיצורים, נוסחאות, חלוקה למקטעים. |
| `src/tts.mjs` | קריאת Gemini TTS (Interactions API). |
| `src/mp3.mjs` | חיבור ה-PCM וקידוד MP3 ב-FFmpeg, ובדיקה חוזרת של הקובץ שנוצר. |
| `src/store.mjs` | חתימות, מניעת כפילויות, נעילה, מגבלת הוצאה, מתג עצירה. |
| `src/storage.mjs` | לאן נשמר ה-MP3. |
| `wix-backend/` | הקבצים שמדביקים ל-Wix IDE. |
| `site/` | הנגן לעמוד הפוסט. |
| `reports/` | דוחות המיפוי והאימות. |

## 2. איך זה בנוי

1. **מקור התוכן** — Wix Blog API דרך ה-backend של האתר. שולף כותרת ותוכן בסדר קריאה
   (`RICH_CONTENT`, ואם אין — `CONTENT_TEXT`). תפריטים, כפתורים, כותרות תחתונות וקוד עיצוב
   לא מגיעים למודל כלל.
2. **הכנה להקראה** — `src/text.mjs` ממיר `%` ל"אחוזים", `ס״מ` ל"סנטימטר", `>` ל"גדול מ-",
   `3/4` ל"3 חלקי 4", מסיר כתובות אינטרנט וניקוד, ומחלק את הטקסט למקטעים בגבולות פסקה ומשפט.
   יש בדיקה שסופרת תווים לפני ואחרי החלוקה ונופלת אם משהו אבד או שוכפל.
3. **הקראה** — כל מקטע נשלח ל-Gemini עם אותה הוראת סגנון, אותו מודל ואותו קול.
4. **הרכבה** — ה-PCM הגולמי של כל המקטעים מחובר לפי הסדר, עם 350 מילי-שניות שקט ביניהם,
   ומקודד פעם אחת ל-MP3. אין הדבקה של קובצי MP3 זה לזה.
5. **אחסון ורישום** — הקובץ נשמר ונרשם באוסף `BlogPostAudio` באתר.
6. **הצגה** — הנגן בעמוד הפוסט שואל את `/_functions/blogAudioInfo` אם יש שמע לפוסט הזה,
   ומציג נגן עם משך ההקראה וקישור הורדה. אין ניגון אוטומטי, ואין הפקת שמע בזמן גלישה.

התוכן של הפוסטים מטופל כנתונים בלבד. שום דבר שכתוב בתוך פוסט לא מבוצע כהוראה.

## 4. הזנת המפתח — עשה זאת בעצמך

אל תשלח את המפתח בצ׳אט ואל תדביק אותו לקובץ בפרויקט.

### 4.1 מפתח Gemini

צור מפתח ב-Google AI Studio (`https://aistudio.google.com/apikey`), ואז הרץ בטרמינל:

```bash
security add-generic-password -s noam-blog-audio -a GEMINI_API_KEY -w
```

הפקודה תבקש את הערך פעמיים ולא תציג אותו. הוא נשמר ב-Keychain של macOS, לא בקובץ ולא
בהיסטוריית הפקודות. הגבל את המפתח ב-AI Studio ל-Generative Language API בלבד.

### 4.2 טוקן העובד מול Wix

צור מחרוזת אקראית פעם אחת:

```bash
openssl rand -base64 32
```

שמור אותה בשני מקומות, עם אותו ערך בדיוק:

```bash
security add-generic-password -s noam-blog-audio -a NOAM_AUDIO_WORKER_TOKEN -w
```

ובאתר: Wix Studio → Settings → Secrets Manager → סוד בשם `NOAM_AUDIO_WORKER_TOKEN`.

> אם ה-Secrets Manager של האתר יקבל בעתיד גם את מפתח Gemini, הוא ייקרא שם `GEMINI_API_KEY`.
> בארכיטקטורה הנוכחית ה-backend של Wix לא קורא ל-Gemini כלל, ולכן הסוד הזה לא נדרש שם.

### 4.3 Gemini API או Vertex AI

`bin/verify-access.mjs` בודק זאת בשבילך. הוא פונה ל-`generativelanguage.googleapis.com`
ומדפיס אילו מודלים זמינים למפתח. אם תקבל 403 או רשימה ריקה, החשבון עובד מול Vertex AI ולא
מול Gemini API, ואז צריך מפתח של AI Studio (או מעבר ל-Vertex, שהוא מבנה בקשה אחר לגמרי —
אין לערבב בין השניים).

## 5. הפעלה ראשונה, לפי הסדר

```bash
node bin/selftest.mjs
```

בדיקה עצמית של כל המנגנון — הכנת טקסט, חלוקה, חתימות, נעילה, מגבלת הוצאה, מתג עצירה,
הרכבת PCM, קידוד MP3 והשוואת פורמט לקובץ הדוגמה, וחשבון הכיסוי של האימות. אין קריאות
ל-Gemini ואין עלות.

```bash
node bin/verify-access.mjs
```

```bash
node bin/map.mjs --source=wix
```

מיפוי ואומדן, בלי קריאות שמע. הדוח נשמר תחת `reports/`.

```bash
node bin/generate.mjs --post=<slug> --source=wix
```

פוסט אחד לדוגמה.

```bash
node bin/verify-audio.mjs --post=<slug>
```

אימות: הקובץ תקין, הקצב סביר, אין מקטע שהוקרא פעמיים, כיסוי המילים מול הטקסט מעל 93%,
אין דיבור שלא מופיע בטקסט, והוראת הסגנון לא הוקראה. **בדיקת אורך לבדה אינה מספיקה,
ולכן האימות מתמלל את הקובץ ומיישר אותו מול טקסט המקור.**

רק אחרי שהדוגמה עברה:

```bash
node bin/generate.mjs --all --source=wix --limit=5
```

קבוצות של חמישה. אפשר לעצור בכל רגע ולהריץ שוב — מה שהושלם לא יופק מחדש.

## 6. מגבלות, עצירה, וטיפול בתקלות

* **מגבלת הוצאה** — `limits.spendLimitUsd` ב-`config.json`, ברירת מחדל 8 דולר. הספירה
  מבוססת על צריכת הטוקנים האמיתית שה-API מחזיר, כולל ניסיונות חוזרים, ונשמרת ב-`state/ledger.json`.
  חריגה עוצרת את הריצה.
* **מתג עצירה** — יצירת קובץ בשם `STOP` בתיקיית הפרויקט עוצרת כל ריצה לפני כל קריאה בתשלום:

  ```bash
  touch ~/Desktop/noam-blog-audio/STOP
  ```

  מחיקת הקובץ מחזירה את הפעילות.
* **מקביליות** — פוסט אחד בכל רגע. קובץ נעילה לכל פוסט מונע שתי ריצות במקביל, ונעילה
  ישנה מ-30 דקות שהתהליך שלה כבר לא חי משוחררת אוטומטית.
* **ניסיונות חוזרים** — עד שלושה לכל מקטע, עם השהיה עולה, רק לשגיאות שמצדיקות זאת
  (429, 5xx, ניתוקים) או כשאורך השמע שהתקבל לא סביר ביחס לאורך הטקסט.
* **המשך אחרי תקלה** — כל מקטע שהושלם נשמר ב-`work/<חתימה>/`. ריצה חוזרת משתמשת בו
  ולא משלמת עליו שוב.
* **הרצה מחדש של הכושלים בלבד**:

  ```bash
  node bin/generate.mjs --retry-failed --source=wix
  ```

## 7. מניעת הפקה כפולה

לכל גרסת שמע יש חתימת SHA-256 מעל: מזהה הפוסט, טקסט ההקראה המלא, המודל, הקול, השפה,
הוראת הסגנון, גודל המקטע ופורמט השמע. אם החתימה זהה לזו שכבר הופקה — הפוסט מדולג.
שינוי בטקסט הפוסט, בקול או בהוראת הסגנון משנה את החתימה ולכן מפיק גרסה חדשה. שום דבר אחר לא.

## 8. פרסומים חדשים ובדיקה תקופתית

* `backend/events.js` מסמן פוסט שנוצר או שהשתנה, ומכבה את השמע של פוסט שהוסר.
* `jobs.config` מריץ `sweepBlogAudio` כל שעה: מסמן פוסטים שהטקסט שלהם השתנה, ומכבה
  שמע של פוסטים שאינם מפורסמים עוד.
* העובד המקומי שואל את האתר מה חסר:

  ```bash
  node bin/generate.mjs --from-queue --source=wix --limit=3
  ```

* להרצה אוטומטית כל שש שעות: העתק את `schedule/com.noamdoron.blog-audio.plist`
  אל `~/Library/LaunchAgents/` והרץ `launchctl load`.

**רק תוכן שפורסם לציבור מעובד.** נקודת האמת היא Wix Blog API, שמחזיר פוסטים מפורסמים בלבד;
`blogAudioRegister` מסרב לרשום שמע לפוסט שאינו מפורסם, ו-`blogAudioInfo` לא מחזיר מקור שמע
לפוסט כזה — כך שהנגן נעלם מיד. הסריקה התקופתית גם מכבה את הרשומה.

## 9. הצבה באתר

1. **CMS** — צור את האוסף `BlogPostAudio` לפי `wix-backend/COLLECTION_BlogPostAudio.md`.
2. **Secrets Manager** — הוסף את `NOAM_AUDIO_WORKER_TOKEN`.
3. **Backend** — העתק את `wix-backend/blog-audio.js` ל-`src/backend/blog-audio.js`,
   הוסף את התוכן של `http-functions.SNIPPET.js` לסוף `src/backend/http-functions.js`
   הקיים (אין להחליף את הקובץ — יש בו את המסלולים של נועם AI),
   והוסף את `events.SNIPPET.js` ל-`src/backend/events.js`.
4. **jobs.config** — הוסף את התוכן של `wix-backend/jobs.config` לקובץ `jobs.config` של האתר.
5. **נגן** — רשום Custom Element בשם `noam-audio-player` שמצביע על
   `site/noam-audio-player.js` (יש להעלות אותו לאותו אחסון סטטי של שאר הנכסים),
   והצב אותו בעמוד הפוסט מתחת לכותרת. אם Custom Element אינו אפשרי, השתמש
   ב-`site/audio-player-embed.html` והעבר לו את ה-slug.
6. פרסם, ואז הרץ `node bin/verify-access.mjs` — הוא יאשר שהנקודות עלו.

## 10. אחסון

ברירת המחדל (`config.json` → `storage.backend`) היא `github-pages`: הקובץ נשמר תחת
`blog-audio/` במאגר הנכסים הסטטי שכבר משרת את תמונות האתר, ומקושר בכתובת מלאה — אותה תבנית
שכבר קיימת באתר. הסרת פוסט מפרסום מסירה גם את הקובץ.

לחלופה `wix-media` (שמירה ב-Media Manager של האתר) שנה את `storage.backend`. המסלול כתוב,
אך תגובת ההעלאה לקובצי שמע טרם נוסתה באתר הזה — הרץ פוסט אחד ובדוק את המזהה שחוזר לפני מעבר מלא.
