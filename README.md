# noamdoronmath-worksheets

מערכת דפי העבודה במתמטיקה של noamdoronmath.co.il — קובץ אחד לכל תשע הכיתות (א׳–ט׳), מוטמע כ-iframe בוויקס.

## מה יש בריפו

| קובץ | תפקיד |
|---|---|
| `index.html` | הקובץ הראשי. כל 9 הכיתות, מזהה כיתה אוטומטית מכתובת העמוד. זהו הקובץ שמפורסם ב-GitHub Pages. |
| `grades-embed-home.html` | ה-embed של עמוד הבית — 9 כרטיסי כיתה + מתג יסודי/חטיבה. מוטמע בעמוד הבית בוויקס. |
| `tools/validate.js` | סקריפט בדיקה — מריצים לפני כל פרסום (ראו "בדיקה לפני פרסום" למטה). |

שני קבצי ה-HTML עצמאיים לחלוטין: HTML+CSS+JS בקובץ אחד, בלי build, בלי npm, בלי תלויות חוץ מגופני Google Fonts.

## איך זיהוי הכיתה עובד

בראש ה-`<script>` ב-`index.html`:

```js
var FORCE_GRADE = 0;
```

`detectGrade()` בודקת לפי הסדר הזה, ועוצרת בהתאמה הראשונה:

1. `?grade=N` בכתובת (1–9)
2. תבנית `worksheetsforNthgrade` (או `1st`/`2nd`/`3rd`) בכתובת, ב-`document.referrer`, ב-`window.parent.location` או ב-`location.ancestorOrigins`
3. אם שום דבר לא זוהה — ברירת המחדל היא **כיתה ז׳**

לקיבוע ידני של כיתה (למשל לבדיקה): משנים את `FORCE_GRADE` ל-1 עד 9 ושומרים.

**הערה חשובה ל-iframe בוויקס:** ה-iframe יושב על דומיין אחר (github.io מול noamdoronmath.co.il), כך שזיהוי לפי `referrer`/`ancestorOrigins` לא תמיד אמין בכל הדפדפנים. לכן בכל קטע ה-iframe שמוטבע בוויקס יש `?grade=N` מפורש בכתובת — זה המנגנון האמין, ואין לבטל אותו.

## מבנה הנתונים

- **`DATA`** — אובייקט שמפתחו מספר כיתה (1–9). לכל כיתה שלושה שדות:
  - `links` — מזהה נושא ← `{ a, b, c }` (שלושת מזהי ה-PDF: רמה א׳, רמה ב׳, מצוינות). נושא בלי רמות מיוצג כ-`{ one: "..." }`.
  - `groups` — קבוצות הנושאים ושמן, לפי סדר התצוגה. כל קבוצה: `{ key, name }`.
  - `topics` — לכל נושא: `id` (מספר), `ic` (מפתח אייקון), `g` (מפתח קבוצה), `t` (כותרת), `d` (תיאור, אופציונלי).
- **`BASE`** — קידומת כתובת ה-PDF (`https://www.noamdoronmath.co.il/_files/ugd/d8e7ad_`). הקישור המלא נבנה כ-`BASE + hex + ".pdf"`.
- **`ICONS`** — מילון SVG לפי מפתח. הערך של `ic` בכל נושא חייב להתקיים כאן.
- **`SEARCH_TERMS`** — אינדקס מילות-חיפוש נסתרות: כיתה ← מזהה נושא ← מחרוזת מילים מופרדת ברווח. משמש את מנגנון החיפוש (`topicMatches`) כדי למצוא נושא גם לפי מילים שלא מופיעות בכותרת.

## חוקי ברזל בעריכה

- **אין לגעת במזהי ה-PDF (32 תווי hex).** הם אומתו אחד־אחד מול קובצי המקור באתר.
- כל נושא ב-`topics` חייב שורת `links` תואמת (אותו `id`), ולהפך — אסור יתומים בשני הכיוונים.
- `ic` של כל נושא חייב להיות מפתח קיים ב-`ICONS`.
- `g` של כל נושא חייב להיות מפתח קיים ב-`groups` של אותה כיתה בדיוק.
- אין להוסיף קבצים של מורה / מפתחות תשובות — המערכת היא לתלמידים בלבד.
- סדר הרמות בתצוגה קבוע: רמה א׳, רמה ב׳, רמת מצוינות (מצוינות תמיד עם ★ בזהב).

## איך מוסיפים / מעדכנים נושא

1. פותחים את `index.html`, מאתרים את הכיתה הרלוונטית בתוך `DATA`.
2. מוסיפים איבר חדש ל-`topics` עם `id` חדש וייחודי בתוך אותה כיתה, ו-`g`/`ic` שכבר קיימים (או אייקון חדש שמוסיפים ל-`ICONS`).
3. מוסיפים איבר תואם עם אותו `id` בתוך `links` של אותה כיתה — שלושת מזהי ה-PDF (`a`,`b`,`c`) או `one` בלבד אם אין הפרדה לרמות.
4. (רשות) מוסיפים ערך תואם ב-`SEARCH_TERMS[כיתה][id]` עם מילות מפתח נוספות לחיפוש.
5. מריצים את בדיקת האימות (למטה) **לפני** commit ופרסום.

## בדיקה לפני פרסום

```bash
node tools/validate.js index.html
```

הסקריפט בודק (בלי תלות במספר הנושאים בפועל, כך שהוא ימשיך לעבוד גם אחרי שמוסיפים נושאים בעתיד):

- תחביר JS תקין בתוך ה-`<script>` (בדיקה אמיתית עם `node --check`, לא ניחוש)
- שלכל נושא יש `links` תואם, ולהפך
- ש-`ic` של כל נושא קיים ב-`ICONS`
- ש-`g` של כל נושא קיים ב-`groups` של אותה כיתה
- שכל מזהה PDF תואם בדיוק לתבנית `^[0-9a-f]{32}$` ושאין אף מזהה כפול בכל הקובץ
- (אזהרה, לא שגיאה) ערכי `SEARCH_TERMS` שמצביעים על `id` שכבר לא קיים

קוד יציאה `0` = אפשר לפרסם. קוד `1` = יש שגיאה של ממש, לא לפרסם לפני שמתקנים.

## איך בונים מחדש / מפרסמים גרסה חדשה

אין build. משנים ישירות את `index.html` (ו/או `grades-embed-home.html`), מריצים את `validate.js`, ועושים commit + push ל-`main`. GitHub Pages מתעדכן אוטומטית תוך דקה-שתיים מכל push לענף `main`.

| כיתה | slug בוויקס |
|---|---|
| א׳ | `/worksheetsfor1thgrade` |
| ב׳ | `/worksheetsfor2thgrade` |
| ג׳ | `/worksheetsfor3thgrade` |
| ד׳ | `/worksheetsfor4thgrade` |
| ה׳ | `/worksheetsfor5thgrade` |
| ו׳ | `/worksheetsfor6thgrade` |
| ז׳ | `/worksheetsfor7thgrade` |
| ח׳ | `/worksheetsfor8thgrade` |
| ט׳ | `/worksheetsfor9thgrade` |

עמוד הבית (`grades-embed-home.html`) מקשר לכתובות האלה דרך אובייקט `PAGES` בראש ה-`<script>` שלו. אם slug של דף כלשהו משתנה בוויקס — מעדכנים את הערך המתאים שם, ותו לא.

## מה לא לעשות

- לא לשנות עיצוב, צבעים או מבנה כרטיסים בלי בקשה מפורשת.
- לא "לתקן" את ה-slugs לאנגלית תקנית (`1st` במקום `1th`) — הבחירה מכוונת, והקוד תומך בשתי הצורות.
- לא להסיר את מנגנון החיפוש (`SEARCH_TERMS` + `topicMatches`) — הוא נבדק מול 23 תרחישים.
- לא לגעת במזהי ה-PDF הקיימים.

## נקודות פתוחות (טרם הוכרעו)

1. כותרות ה-SEO של עמודי א׳–ו׳ בוויקס עדיין מציגות "כיתה ח׳" (שארית משכפול עמוד) — דורש תיקון ידני בעורך וויקס, לא בקובץ הזה.
2. שני נושאים ביסודי מופיעים בשתי כיתות: "מיון משולשים" (ג׳/ד׳) ו-"שברים על ישר והשוואה" (ד׳/ה׳). ייתכן שזו ספירלה פדגוגית מכוונת — לא לגעת בלי אישור.
3. ב-`SEARCH_TERMS` של כיתה ט׳ יש 5 רשומות יתומות (מזהי נושא 18, 25, 29, 31, 32 שכבר לא קיימים ב-`topics`, שריד מעדכון קודם). לא שוברות כלום בפועל — `validate.js` יתריע עליהן — אך שווה ניקוי בעדכון נוח.
