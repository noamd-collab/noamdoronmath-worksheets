# חיפוש באתר: דוח השוואה ומסירה

**ענף:** `claude/site-search`
**בסיס:** `claude/site-journey-tests` (`c1d487a`). הבסיס הזה כולל את תשתית בדיקות הדפדפן (PR 58), את תיקוני הטיפוסים (PR 56) ואת שינויי `WorksheetsClient` (PR 55). לכן אין כאן קונפליקט ואין עבודה כפולה.

## 1. מה היה

**החיפוש היחיד באתר** היה מסנן הנושאים בתוך `/worksheets` (`src/lib/search.ts`):
- עבד רק בכיתה שנבחרה, ובאופן אופציונלי גם באותה שכבה (`cross=1`).
- חיתוך תחיליות וסיומות גורף, והתאמה לפי תחילית מילה ("כדור" תאם "כדורגל").
- כל מילה חייבת להתאים, כולל "כיתה" ו־"ה". לכן "שברים כיתה ה" לא מחזיר דבר.
- אין דירוג: הנושאים מוצגים בסדר הקטלוג.
- לא כולל דפי הסבר ופוסטים.
- אין חיפוש כללי מכל מקום באתר.

**מילות החיפוש בקטלוג:** הממצא `SEARCH_TERMS_MISPLACED` מ־PR 59 (18 מקרים) הראה שבחלק מהנושאים מילות החיפוש שייכות לנושא אחר. דוגמה: חיפוש "פיתגורס" בכיתה ז׳ מציג "שאלות מילוליות באמצעות משוואות".

## 3. מה נבנה

### מנוע (`src/lib/siteSearch/`)

**נרמול (`normalize.ts`):**
- מסיר ניקוד, גרש וגרשיים.
- מקף עברי ומקפים הופכים לרווח.
- אותיות סופיות מאוחדות.
- "גיאו" ו־"גאו" מאוחדים.
- "וו" ו־"יי" מאוחדים, אבל לא ב־"ריבועיים", כדי שלא יתמזג עם "ריבועים".

**צורות מילה:**
- **ריבוי:** ים / ות / יות.
- **סמיכות ונקבה:** ת←ה, ית←י. מופעלות רק כשהמילה שמתקבלת כתובה כך באתר. כך "מערכת" לא הופכת ל"מערך".
- **אותיות שימוש (ו/ה/ב/ל, ו־מה/שה):**
  - מוסרות רק כשהשארית היא מילה שכתובה באתר.
  - יש רשימה סגורה של מילים שאסור לחתוך: המשך, הקטנה, למידה, לחזק, בטוח, השלמה, השלמת.
  - אין חיתוך גורף.

**הבנת השאילתה (`query.ts`):**
- **כיתה בשאילתה:** "כיתה ה", "לכיתה ז׳", "כיתה 5". הכיתה מחייבת ומילותיה מוסרות.
- **מילות ניסוח לא חובה:** "הילד שלי מתקשה", "דפי עבודה", "איך" ודומיהן.
- **3 מילים נרדפות עם ראיה מהאתר** (כולל צורת הרבים של הראשונה):
  - שבר עשרוני ↔ מספר עשרוני
  - תיכון → חטיבה עליונה
  - חילוק ארוך ↔ חילוק מאונך

**תיקון כתיב:**
- רק למילה שאינה קיימת באתר, באורך 4 אותיות ומעלה.
- מרחק של אות אחת לכל היותר, מתוך אוצר המילים של האתר.
- התיקון מוצג כהשערה ולא כוודאות.

**דירוג:**
- סדר המשקלות: כותרת > תת־נושאים > מילות חיפוש > קבוצה > תיאור.
- מדרגת כיסוי כותרת: כותרת זהה גוברת על אזכור חלקי.
- עדיפות קלה לפי סוג: דף עבודה > הסבר > מאמר.
- כשהציון שווה: לפי כיתה, ואז לפי סדר הקטלוג.

**הבחנות מתמטיות** (נבדקות ביחידה):
- היקף ≠ שטח ≠ נפח
- שטח פנים ≠ נפח (גליל ומנסרה)
- חזקה ≠ שורש
- "נוסחת השורשים" ≠ "שורשים"
- זוויות קודקודיות ≠ קודקוד של מצולע

### אינדקס בזמן build (`scripts/build-search-index.ts` → `src/data/search-index.v1.json`)

**תוכן האינדקס:** 480 מסמכים:
- 325 כרטיסי קטלוג
- 95 דפי הסבר
- 60 פוסטים

**פרטי הבנייה:**
- **דטרמיניסטי:** בדיקת יחידה משווה את הקובץ השמור לבנייה מחדש. אפשר להריץ גם `npm run check:search-index`.
- **קישורי PDF:** נבנים דרך `loadCatalog()`, כמו בעמוד הקטלוג (Wix CDN). את הבאג הזה תפס מבחן דפדפן.
- **גודל:** 394KB, ו־65KB ב־gzip.

**שיוך הסבר או פוסט לנושא:**
- **התנאי:** הדף מקשר לנושא, באותה כיתה, ויש מילה משותפת בכותרות.
- **פוסט בלי כיתה משלו** שמקשר לכמה כיתות לא משויך.
- **התוצאה:**
  - 93/95 דפים ו־31/60 פוסטים משויכים.
  - כל השאר מופיעים כתוצאה עצמאית.
  - פירוט מלא ב־`docs/search/index-build.json`: 124 קישורים אומתו, 32 לא שויכו, לכל אחד יש סיבה.
- **הדפים שלא שויכו:**
  - `/coordinate-plane-grade-8` ← 55 "סינתזה גאומטרית"
  - `/statistics-grade-8` ← 16 "ארגון נתונים"
  - שני אלה הם בדיוק המקרים ש־PR 59 סימן.

### מילות חיפוש שגויות (`src/data/search-terms-review.json`)

**איך זה עובד:**
- ההחלטות מוחלות רק על אינדקס החיפוש.
- `index.html` ו־`catalog.v1.json` (קובץ מוגן) לא שונו.
- כל החלטה חלה רק כל עוד בנושא כתובות בדיוק אותן מילים. בדיקה נכשלת אם המקור השתנה.

**מה נבדק:** 18 המקרים מ־PR 59, ועוד 3 מאותו סוג שהתגלו בעבודה:
- **7:47:** מילות "שטח פנים / מעטפת" ישבו על דף הנפח.
- **9:5:** "רדיקל תחום הגדרה" ← 9:17.
- **9:8:** "שיפוע מרחק אמצע קטע" ← 9:15.

**התוצאה:**
- **הועבר (17):** המילים חוזרות על כותרת או תיאור של נושא יעד יחיד באותה כיתה. בדיקה אוטומטית מוודאת לפחות 2 מילים משותפות עם היעד.
- **נשאר (2):**
  - 4:27, "זוויות וקווים במישור". המילים מתאימות לו. זו הייתה התראת שווא של בדיקת PR 59, שלא טיפלה בריבוי.
  - 7:13, דף חזרה על זוויות.
- **הוצא מהאינדקס, ממתין להחלטה (2):**
  - **6:2:** "מכנה משותף שברים חיבור חיסור" על נושא כפל. אין בכיתה ו׳ נושא חיבור שברים.
  - **9:20:** "מקביליות צלעות נגדיות אלכסונים". יש שני מועמדים: 9:7 "המקבילית" ו־9:11 "המלבן".

### ממשק

**עמוד `/search`:**
- **בלי JavaScript:** תשובה שמרונדרת בשרת. טופס GET וקישורי כיתה רגילים.
- **עם JavaScript:**
  - רכיב React נטען ב־`client:idle`.
  - המנוע (5.2KB gz) והאינדקס (65KB gz) נטענים רק כשהמבקר נכנס לשדה או מקליד.
  - החיפוש מתבצע תוך כדי הקלדה (השהיה של 120ms).
- **מצב בכתובת:** `q` ו־`grade` נשמרים ב־URL.
  - ההקשה הראשונה פותחת רשומה חדשה בהיסטוריה. ההקשות הבאות מעדכנות אותה.
  - Enter ולחיצה על כיתה פותחים רשומה חדשה.
  - "חזרה" בדפדפן מחזיר את החיפוש הקודם.

**כרטיס תוצאה:**
- סוג (דפי עבודה / הסבר / מאמר בבלוג), כיתה, תחום ורמה מצומצמת.
- כותרת שבה המילים שנמצאו מודגשות ב־`<mark>`.
- כפתורי רמות: אותם קישורים כמו בקטלוג (`buildWorksheetHref`). תת־נושאים מוצגים בתוך כרטיס ההורה.
- קישורים להסבר ולמאמרים של הנושא.

**כיתה:**
- כיתה שנבחרה או שנכתבה בשאילתה מחייבת.
- כיתות אחרות מוצעות בנפרד ("יש תוצאות גם בכיתות אחרות").

**מצב "אין תוצאות":**
- הצעות לחפש מילה אחת מהשאילתה.
- כיתות אחרות שיש בהן תוצאות.
- ניקוי סינון הכיתה, ניקוי החיפוש וקישור לכל דפי העבודה.

**נגישות:**
- `role="search"`, תווית לשדה ו־`aria-describedby`.
- סטטוס ב־`aria-live`.
- כפתורי הכיתות הם קישורים עם `aria-current`.
- פוקוס נראה לעין.
- RTL, בלי גלילה אופקית ברוחב 360px.

**בטיחות:**
- השאילתה מוצגת כטקסט בלבד. אין `innerHTML` ואין `dangerouslySetInnerHTML`.
- יש בדיקת דפדפן להזרקת `"><img onerror>`.
- העמוד שולח `X-Robots-Tag: noindex, follow` ואינו ב־sitemap.

**שילוב בקטלוג:**
- המסנן ב־`/worksheets` עובר לאותה התאמה עברית. מחרוזות הסטטוס לא השתנו, ובדיקות PR 58 עוברות.
- כשאין התאמה, מופיע קישור "חיפוש „…” בכל האתר ובכל הכיתות".
- בזמן חיפוש מופיע גם קישור "חיפוש בכל האתר ←".

**נקודות כניסה:**
- פריט "חיפוש באתר" בתפריט במובייל.
- קישור בפוטר.
- הכותרת בדסקטופ לא שונתה: באמצע 1280px הוספת פריט גורמת לשבירת השורה לשתיים (ראו החלטה 1 בהמשך).

## 6. החלטות לנועם

1. **אייקון חיפוש בכותרת בדסקטופ.**
   - כרגע יש כניסה רק מהתפריט במובייל, מהפוטר ומהקטלוג.
   - הוספה לכותרת מחייבת לפנות מקום, למשל לקצר את "דפי עבודה לחטיבת הביניים".
2. **מילות חיפוש:**
   - 6:2: להעביר ל־5:10/5:11 או למחוק.
   - 9:20: לבחור בין 9:7 ל־9:11.
   - אחרי ההחלטה כדאי לתקן את `SEARCH_TERMS` במקור (`index.html`), ואז למחוק את ההחלטות מהקובץ.
3. **שיוך דפים:**
   - `/coordinate-plane-grade-8` ו־`/statistics-grade-8` מופיעים בחיפוש כהסבר עצמאי, כי הכפתור שלהם מוביל לנושא אחר.
   - זה המצב שכבר תואר ב־PR 59.
4. **שאילתות אמיתיות:** להוסיף שאילתות של משתמשים למבחן, אם יש יומני חיפוש.

## 7. איך מריצים

```bash
cd headless/astro-poc
npm run refresh:search-index   # בונה את האינדקס אחרי שינוי בקטלוג, בדפים או בפוסטים
npm run check:search-index
npm run eval:search            # מבחן ההשוואה: ישן מול חדש → docs/search/
npx tsx --test tests/site-search.test.ts
npx astro build --config astro.config.preview.mjs && CHROME_PATH=/path/to/chrome npm run test:journeys
```

**שימו לב:** אחרי `npm run refresh:catalog`, או אחרי שינוי בדפי נושא או בפוסטים, צריך להריץ `npm run refresh:search-index`. אחרת בדיקת היחידה נכשלת.
