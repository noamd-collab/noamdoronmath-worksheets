# Additional reviewed Ramzi editions — passive contract v1

This candidate adds a reusable, closed validation path for additional middle-school packages. It does not activate a worksheet. The committed trust index is empty; the request file is absent. The eighteen RAT01/FRQ01/GRW01 source assets remain byte-identical disabled drafts (`reviewRequired:true`, `publishable:false`). No hint text, private answer, additional-package database receipt, or additional-package acceptance claim is published by this passive collection.

## Authority and evidence

The original first567 activation and optional first15 correction keep their existing modules, fixed scope, evidence and validation. This collection explicitly refuses their edition IDs. It does not widen either historical transaction.

A future reviewed package needs all of the following, with exact hashes fixed in a reviewed change:

1. A build-only, content-addressed accepted scope (`noam-reviewed-additional-scope/v1`). This pins package/edition, topic, exactly three levels, worksheet and PDF/native/source/manifest identities, every exercise's eight source-binding fields, all three reviewed hint hashes, the verified payload hash, independent author/reviewer identities and review/Root-acceptance hashes.
2. A compiled trust capsule in `headless/catalog/ramzi-additional-trust.v1.json`. It contains the exact accepted batch metadata, scope/review hashes, and exact readback/evidence hashes. The full source and per-item proof is not imported into SSR.
3. A build request (`ramzi-additional-requests.v1.json`) referencing content-addressed asset, committed DB readback, learning-ID readback, and server scope-enforcement evidence. The public projection contains only four fixed identifiers/hashes per batch, without hint text, answers, item arrays, or local paths. SSR compares each reference with the compiled trust capsule, then validates the fixed package metadata against the current catalog/registry.
4. Exact static native/manifests and an independently reviewed bounded learning-scope profile. Profile schema `noam-reviewed-learning-scope/v1` has exactly `schema,scopeId,status,drawingsAllowed,permittedTools,deferredTools`. Its hash is bound by both accepted source and enforcement evidence. Nongeometry topics cannot enable drawings even when the rest of a synthetic evidence chain is consistently re-pinned.

Evidence files live under `headless/catalog/ramzi-additional-evidence/<sha256>.json`; the loader hashes raw bytes before reading fields. Unknown/missing/duplicate fields, identities, out-of-scope sources, unverified rows, replaced hint cells, missing receipts, self-review, future observations, and substituted SSR references fail closed.

Hashes and status strings are evidence bindings, not proof that SQL ran. Root must review the actual committed transaction and a fresh independent readback before producing the sanitized references. A prepared import, review-status rows, a synthetic fixture, or a local manifest flag alone is never an activation receipt.

## Publication order without a circular dependency

The database review reference binds existing source/review/Root-acceptance artifacts, not a future activation-scope hash. The frozen RAT01/FRQ01 transaction explicitly requires the prepared first15 correction and readback. Its exact whole-table pins also reject a prior GRW insert; the first15 transaction pins all learning IDs. Coordinate the single database writer and sequence before any additive import, or prepare a separately reviewed transaction against a fresh snapshot. This generic code does not authorize the correction, widen either frozen transaction, or require first15 for offline GRW implementation. A separately reviewed verified additional payload and actual bounded import still need fresh readbacks of the new rows/learning IDs and preservation of older data.

After that real readback and server policy verification, create the final accepted scope/trust/request chain. Locally reviewed final assets and existing verified CDN PDFs may be published atomically with the final site activation. A prior passive source deployment is not required. No future deployed commit is invented. Final manifest review flags may change only in an explicitly reviewed derived artifact; author files and PDF/native source bytes stay immutable.

## Remaining activation work

This is passive catalog/readiness compatibility, not a completed server or hint activation. Actual server enforcement of the pinned learning scope and nongeometry drawing denial, fresh DB/learning readbacks, and final accepted asset/scope evidence remain required. Catalog and static site-guide retrieval now include only evidence-validated additional editions, carrying the exact native/edition/PDF identity. With no activation requests, previous navigation is preserved. Auth, CAPTCHA, models, original teacher questions and the original viewer are unchanged.

The native and manifest bodies use existing static asset routes and do not enter the worker. Learning profiles have a static route, but no unreviewed profile is staged. Full-scope proof and validation remain build-only. Budget acceptance requires a real final build with actual receipts, data and profile registrations; the synthetic shape estimate is only an early bound.
