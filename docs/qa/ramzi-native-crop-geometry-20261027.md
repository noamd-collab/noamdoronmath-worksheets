# Native question crop geometry

The normal Brave test W07-Q1 selected G8-T12, level B, question 12ג. Its hint failed with `QUESTION_IMAGE_UNREADABLE`: the configured image was completely blank. The published PDF SHA-256 is `d1c9c0224f34a385d9ab3d91c9988caa39bda20071f871de858c40cdf6d61d4c`, matching the manifest. On page 11, the old crop covered 677.25–808.21 points; the question introduction, graph and all three parts occupy approximately 49–480 points.

The replacement is measured by the existing `scripts/build-student-manifest.py` against those exact PDF bytes and its matching native export. The q12 crop is now page 11, y=0.058141, h=0.569381; the selected-part pin is y=0.533696. All three parts share the complete question image. The solver still receives the original selected-part prompt and still requires successful image analysis.

The same synthetic-position family occurs in 20 canonical PDFs: 401 questions and 1,526 subsections. All their old pins used x=0.83. A source audit found 1,038 old crops excluded the measured selected-part pin and 149 crop sets were vertically disjoint from the measured question band. The inventory first found 184 shared-figure groups (717 subsections) whose sibling crops had no common image; checking their full PDFs established the larger 1,526-subsection scope. These are geometry measurements, not claims that every old request failed.

`repair-native-crop-geometry.py` verifies the PDF and native-export hashes, requires a complete native question/part match with no parser issues, and copies only measured pin/crop fields and question page metadata. Exact text, prompts, source identity, native bindings and vision requirements remain unchanged. Root and public copies match. The viewer refreshes its manifest URL and OCR cache namespace; conversation history remains in its original namespace.

The 20 teacher source-crop JSON derivatives were regenerated with the existing PDF measurement tools as well. Their 1,526 subsection identities, labels and text stay fixed; only measured crop/marker fields change.

Validation: 20/20 PDF rebuilds had zero mapping issues. Independent comparison checked every repaired coordinate and unchanged non-geometry field, plus containment of all 401 question markers and 1,526 selected-part pins. A visual review covered one affected figure example from each of the 20 PDFs, including W07-Q1; this does not claim visual review of all 401 questions. Four repair-tool guard tests, the complete deterministic unit suite (961 passed, two skipped after the drawing-intent regressions), and the CI servable build passed. The corrected release still requires a new ordinary-browser hint/drawing acceptance run; the pre-fix Brave baseline remains separate evidence.

The same baseline exposed W06-Q2: in G8-T50 level C question 3ד, the hint word `בנוסחת` accidentally matched the construction imperative `בנו`. Explicit Hebrew token boundaries now let the existing AC segment be highlighted. The native consumer also accepts only the two verified one-level site-B/native-a identities (G8-T01 and G8-T35), and an explicit drawing-button flag can plot a single authored formula from the exact question/item.
